# Expected Output Shape

## Orientation

- State that the request is broad and architecture-affecting.
- Do not edit files yet.
- Identify that `zoom-out` and `grill-with-docs` are appropriate before implementation.

## Proposed Plan

- Map the relevant module and callers.
- Identify current behavior, invariants, and persistence/API contracts.
- Define acceptance criteria with the user.
- Propose one narrow vertical slice or advisory architecture report.
- Name the test strategy and performance baseline.

## Human Gate

- Ask for approval before any broad refactor, dependency, public API, or persistence change.

## Must Not Say

- "I'll refactor the module now."
- "This should be faster" without a measurement plan.
